## Common behavior and limits

- The nine PowerShell hooks preserve provider-specific known read-only lists, authorize declared local workspace/effective SDD-root writes outside CWD through the shared policy, and return an observable denial for unclassified tools or invalid/empty input. OpenCode and Hermes native evaluators apply equivalent handling.
- Catch-all configuration and hook/evaluator payloads were exercised by `scripts/validation/Assert-ProviderCatchAllConfiguration.ps1` and `scripts/validation/Assert-LocalSddWriteConformance.ps1`. These verify shipped adapter behavior, not live host delivery or successful filesystem writes.
- Provider documentation supports the configured catch-all mechanism for all ten registered providers. No host parity is inferred. Live host behavior and ACL/provider sandbox outcomes are `not reproduced`; Cursor, Codex, and Copilot legacy path-secret fixtures additionally reported Windows junction creation as `Access is denied`.
- An unknown tool reaches the guard and is denied with a provider-visible signal unless classified read-only. This intentionally favors an observable block over silent authorization when semantics are unknown.
