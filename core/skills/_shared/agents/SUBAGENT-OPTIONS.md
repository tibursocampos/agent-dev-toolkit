# Subagent options reference

Common contract for adapter-specific model and effort options used by `orchestrate-*` and `developer` session selection (US01), and by `adt-settings` (US02). This contract is orthogonal to `SPAWN.md`, which governs when to delegate, and `SUBAGENT-MODEL.md`, whose default is to omit `model` and inherit from the parent.

Install path after sync: `{{TOOLKIT_ROOT}}/skills/_shared/agents/SUBAGENT-OPTIONS.md`

## Scope and non-goals

This file defines provenance and consumption rules for adapter options; it is not a fixed model catalog or a generic settings registry. It adds no roles, favorites, editable support flags, hooks, commands, modes, `hostCeiling`, `spawn_limits`, `SettingsRegistry`, or adjustable limits. It does not configure the parent's model. A model name, plan, or `subagents=native` capability does not prove that an option is available or supported.

## Pair contract

The internal selection is always a complete `{model, effort}` pair. `inherit` is a user-interface choice and is never persisted as a string. Unless the complete pair is supported by the effective adapter surface, omit both arguments and any composite field that would encode them, then inherit the parent's model and effort. The internal pair does not require adapters to use identically named native arguments.

## Preference shape

The only new preference is `subagent_models.default`: complete `{model, effort}` object or absent. Absent means inherit; inherit is never persisted as a string. Reading never writes or migrates preferences. Before offering reuse, validate both values against the active adapter, surface, and current supported choices; the preference has no stored adapter/surface provenance. An unreadable, incomplete, or incompatible default is ignored without deleting or rewriting content; any warning names only the field and reason. Reset removes only `default` and preserves unrelated keys. A saved selection may preselect the session question only after validation, but never answers it.

US03 may update this same field only after the parent used the complete active pair and the operator explicitly confirms that it worked. That confirmation alone is sufficient; do not require logs or captures. Inheritance, an unused or refused pair, missing confirmation, or a failed write preserves the prior value. Change no other preference key and add no history or proof metadata. Follow the existing `adt-settings/SKILL.md` field-scoped write/read-back safeguards; its explicit query, save, and inherit operations remain compatible.

When US02 saves a value and the preferences file is absent, it uses the existing structure from `scripts/_lib/Initialize-SddPreferences.ps1` (`New-ToolkitDefaultPreferencesObject`) and adds the new key only with a value to save. It does not invent a file format. The installer does not seed `subagent_models` (`NO_CHANGE`).

## Evidence states

`DOCUMENTED` means primary documentation was consulted. `SESSION_SCHEMA` means a tool signature was exposed in the identified session context. `RUNTIME_VERIFIED` requires real execution evidence. `UNKNOWN` records a gap and the consultation needed to resolve it. Documentation, schemas, fixtures, and publication do not establish runtime application. A child agent's self-report does not prove the model or effort actually applied.

## Session-start discovery

Discover the active host's model choices before asking the session question. Use only the active surface's read-only picker or exposed spawn-tool schema and its adapter row; do not use a published example, another product surface, or a stale cache as an account catalog. Treat `subagent_models.default` as reusable only when it is complete and both its model and effort are supported by the active adapter and surface now; a saved pair does not carry adapter or surface provenance. If the preference cannot be read or the pair is not eligible, preserve it and omit the reuse option. In the US03 `choose_model` branch, ask for a model first, then intersect that model's supported efforts for the active adapter/surface with `low`, `medium`, and `high`; display only that intersection in canonical order. Support evidence remains `DOCUMENTED`, `SESSION_SCHEMA`, or `RUNTIME_VERIFIED` and must not be promoted between states. Never build or display a cartesian model/effort list. If the intersection is empty or unsupported, skip the effort question and inherit the parent's model and effort.

## Consumption rules

- US01 and `adt-settings` use the same ADP row for the effective surface and the same eligible pairs.
- A client, version, surface, policy, or route change requires eligibility to be checked again; do not add an editable support cache.
- After `subagents=native` and `orchestrator_mode` are resolved, the parent presents one initial session question, and its answer applies to all subagents. In the US03 `choose_model` branch, model and effort are separate questions: select a model from the active adapter/surface, then display only its supported `low`, `medium`, and `high` efforts. An empty effort intersection skips that question and inherits. Never show a cartesian list of model/effort combinations. A question is never repeated for each spawn (D-032).
- An explicit user request to use subagents satisfies delegation intent; it does not authorize a model/effort pair. If the model-choice question is pending, a clarification does not trigger a duplicate question or a second yes/no inherit prompt.
- Non-interactive sessions and O3 continuous/queued work use the session choice made at the start. Missing or unreadable configuration means omit both arguments and inherit.
- If the host refuses a pair, including a repeated request for that pair, re-evaluate eligibility once, then inherit the current session parent's full pair and continue the task. Failure never stops the work (D-035).
- Validation of an alternate pair is manual by the operator; the agent never performs it automatically (D-031).
