## Before O3 dispatch

Confirm only that the work is authorized by the approved PLAN, the selected PLAN path is valid, and the first step is eligible by its dependencies and state. Inspect relevant partial work before dispatch.

Do not require Memory Bank initialization, ANALYSIS/ARCH/SEC mirrors, CONTINUITY, SESSION, claims, TASKS, a receipt preflight, structural validation, or a universal checklist. Read optional existing context when it can materially affect the step. Ask a focused question only when behavior, acceptance, scope, necessary access, or an implementation decision is unresolved.

The child must use `adt-sdd-develop`, work on one step, and remain within the PLAN's approved scope. The parent reviews the returned change and evidence and reconciles the canonical PLAN before another dispatch.

## Relevant risk context

Read existing architecture, security, data, API, or memory-bank evidence when it is relevant to the assigned step. Distinguish observed facts from inference and proposal. A concrete material gap can block affected work and receive focused investigation; brownfield status or an absent sidecar alone cannot.
