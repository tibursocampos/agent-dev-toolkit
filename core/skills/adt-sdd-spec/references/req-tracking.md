## Requirement references

Use stable IDs such as `REQ-001` when they make it easier to refer to behavior across the PRD, PLAN, discussion, or tests. IDs are optional; a clear prose description is sufficient when the work is small or the relationship is evident.

When IDs are used, preserve them through planning where useful. Do not require exact numbering, a fixed number of requirements, a mandatory mapping table, or a prescribed change-history record. If a material decision changes, explain the current behavior and decision plainly so downstream work can reconcile it.
