## O2 input and story selection

Resolve the feature path through `STORAGE.md`; reject traversal and paths outside the authorized feature root. Read the current FEATURE and story records needed to understand the backlog. FEATURE, CONTINUITY, CHANGE, TASKS, Memory Bank, and ANALYSIS/ARCH/SEC sidecars are optional context unless a concrete material decision or the user's approved scope requires them.

Discover current US/TS stories and dependencies from canonical records. Reuse existing PRDs/PLANs as current inputs when relevant, but do not infer completion or approval from file presence alone. Resume from the next useful preparation action. If an old sidecar conflicts with current canonical evidence and the conflict affects the outcome, state that conflict and pause only affected work.

## Questions and blockers

Ask only for information that could materially change behavior, acceptance, scope, required access, or an implementation choice. Identify which story or dependency is affected. Keep unrelated stories eligible. Minor questions and optional technical improvements remain visible but do not block.

Brownfield status alone does not require ARCH/ANALYSIS/CHANGE artifacts, a document validator, or a preflight. Inspect existing behavior when it is relevant to the requested change; record the current behavior, intended change, concrete risks, and evidence limits in the PRD or PLAN.

## Memory Bank

Read relevant named files only when they contain useful context. O2 does not require Memory Bank initialization, refresh, status fields, or a CONTINUITY mirror.
